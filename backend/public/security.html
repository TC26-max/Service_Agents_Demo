Security

Grounded is a public demo with no accounts, no database and no stored conversations, so the things worth protecting are the model provider's bill, the honesty of the answers, visitors' privacy and the site itself. This page sets out what can go wrong, what stops it, and where each control is tested.

Who might attack

  • A curious visitor, the expected case.
  • A prompt injector, who tries to make an assistant break its rules or leak its context.
  • A cost abuser or bot, who sends many requests to run up the bill.
  • A scanner, who asks for well-known admin paths; those land in a honeypot that answers like any missing page.
  • A researcher, who reports what they find (see Disclosure).

Entry points

  • POST /api/chat: chat answers and the Retrieval X-ray (mode retrieve).
  • POST /api/transcribe: voice, behind a short-lived signed token.
  • POST /api/arena: the Red Team Arena, a sandboxed copy of the support bot with its own budget.
  • GET /api/health: status; the deep check calls the model at most a few times a day.
  • POST /api/csp-report: browser reports of blocked content, reduced to directive and origin.
  • Static files under /, from the public folder only.
  • Knowledge-base edits, which live in the visitor's tab and travel with each request, capped at 240 characters.

Trust boundary

Everything the browser sends is untrusted, including the conversation history, edited passages and the requested mode. The functions hold no state between requests beyond counters. The model provider is a third party that receives the system prompt, the retrieved passages and the visitor's message. The model's reply is untrusted until the output rules pass it, and the page prints it as text, never as HTML.

Dependency watch

A scheduled workflow (.github/workflows/depwatch.yml) reads package-lock.json and the workflow files every day, asks the OSV database for known advisories, follows each to its CVE record (the CNA's score first), and checks the CISA Known Exploited Vulnerabilities catalog and FIRST's EPSS exploit-probability score. A known-exploited issue, or a high-severity or likely-exploited issue in anything the site or its pipeline runs, fails the workflow; the workflow's badge in the README shows the latest result, and each run's summary lists every advisory it found. The deployed functions themselves have no npm dependencies.

This product uses data from the NVD API but is not endorsed or certified by the NVD. The NVD is consulted only when a CVE record carries no score from its CNA or from CISA.

Red Team Arena

Anyone can attack a sandboxed copy of the support assistant on the Arena tab: five levels mapped to the table above, each attempt judged twice by deterministic code, once on the model's raw reply and once on what reaches the screen. The scoreboard keeps counts only; nothing typed there is stored.

Disclosure

Report security issues through GitHub's private vulnerability reporting: open a private report. The same address is in security.txt, and the full policy, with what is in scope and the safe harbor, is in SECURITY.md.

Please do not load-test the live site or enter real personal or payment details. A win in the arena counts as a finding: send what you typed and when.
